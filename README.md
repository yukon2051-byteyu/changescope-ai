# ChangeScope AI

**変更の前に、まだ確認していないことを見つけるAI。**

システムの入れ替えや承認フローの見直しなど、組織で何かを変えるときに、業務・システム・部門・データ・社内規程のつながりから「誰に・どこに影響するか」を根拠つきで示し、さらに **「まだ確認していないこと」と「誰に何を聞けばよいか」** を具体的に挙げるツールです。

> 個人開発のポートフォリオです。サンプルデータはすべて架空の会社（サンプル商事株式会社）のものです。

---

## 解決したい業務課題

変更の影響調査は、担当者の経験と記憶に頼りがちです。

- 影響は直接つながる相手だけでなく、**2段・3段先**にも伝わる（例：勤怠管理システム → 勤怠実績データ → 月次給与計算 → 人事部）。直接のつながりだけを調べると漏れる
- 変更を担当する部門からは、**別の部門に遠回りで伝わる影響**が見えにくい
- 「たぶん連携している」「確認していない」つながりが、確定した事実のように扱われる
- その結果、リリース直前や本番後に「その連携は聞いていない」「その部署には伝わっていない」が起きる

ChangeScope AI は、これを **ヒアリングの抜け漏れを見つける問題** として扱います。

## 主な機能

| 機能 | 内容 | AI |
|---|---|---|
| 依存関係の登録 | **Excel**にまとめて書く／**図で入力する**（ヒアリングしながら1つずつ。はじめての人向けのチュートリアルつき） | 使わない |
| **文章・資料から作る** | 業務の流れを書いた文章や資料から、AIが**図のたたき台**（要素とつながりの候補）を作り、人が選んで登録し、図でマウスで直す。文章からは確定できないつながりも「AIの推測」として出し、「未確認」で登録する。資料からは分からないこと（確認先つき）も挙げる | 使う |
| 影響分析 | 変更対象から、つながりを最大8段たどり、直接・間接の影響、影響の経路と根拠資料、影響度を表示 | 使わない |
| 誰に影響するか | 影響を受ける部門・担当者を、影響の大きい順に一覧 | 使わない |
| 要確認のつながり | 「推定」「未確認」のつながりを、**確かめると分かることが多い順**に、確認先つきで表示 | 使わない |
| 見落としやすい影響・見落としチェック | 別の部門に2段以上先で伝わる影響、データ移行・連携・規程・切り戻しなどの確認観点 | 使わない |
| 結論・次にやること | 影響範囲の大きさ（大・中・小）と、確認する相手と事項を手順で表示 | 使わない |
| **変更案を比べる** | 2つの変更案の、影響の広さ・関係する部門・要確認のつながり・見落としやすい影響・確認すべき観点・費用と期間（入力がなければ「要見積もり」）を並べ、「Aだけ・Bだけ・両方」に分けて示す。どちらが良いかは決めない | 使わない |
| PDFレポート | 影響分析（AIの確認漏れを含む）と、変更案の比較の結果をPDFで持ち帰る | 使わない |
| **AIで確認漏れを調べる** | 確認していないことを10件ほど挙げ、**確認先と、そのまま聞ける質問文**を示す。部門別の調整ポイント、トラブルの予測、見落としがちな費用、推奨する進め方、登録データにない影響の推測も出す | 使う |

### 設計で大事にしたこと

- **確実な処理はプログラム、あいまいな処理だけAI。** 影響のたどり方・判定はすべて Python で行うので、同じデータからは毎回同じ結果が出ます。AIが止まっても、分析はそのまま使えます。
- **AIの回答をそのまま信用しない。** AIには分析結果をつながりの番号つきで渡し、根拠にした番号を答えさせます。番号が実在すれば「登録情報にもとづく」、なければ「AIの推測」と分けて表示します。費用や期間の数字はAIに作らせず「要見積もり」に置き換えます。
- **AIが作ったものは「候補」として、人が選んで登録する。** 文章・資料から作る候補には、根拠にした文を一字一句そのまま抜き出させ、その文が本当に書いてあるかをプログラムで照合します。AIが作ったつながりは「確認済」にはせず、「推定」（書いてある）か「未確認」（AIの推測）で登録します。
- **「まだ確認していないこと」を目立たせる。** 推定・未確認のつながりは、図では点線、一覧では先頭に表示します。

## 画面の構成

| ページ | 内容 |
|---|---|
| ホーム | ツールの紹介と「サンプルで試す」 |
| 使い方・用語について | 手順・結果の見方・仕組み・よくある質問 |
| データ管理 | サンプルの読み込み、Excelテンプレートのダウンロード・アップロード |
| 文章・資料から作る | 文章（アクセスコード不要）や資料（アクセスコードが必要）から、AIが図のたたき台を作る。選んで登録すると「図で入力する」が開く |
| 図で入力する | いま見ている要素を真ん中に、左に影響元・右に影響先（2段先まで）を並べた図で、つながりを登録・修正する。Excelに保存できる |
| 影響分析 | 変更内容を入力して分析。結果の下で「AIで確認漏れを調べる」。PDFでダウンロード |
| 変更案を比べる | 2つの変更案を並べて比べる。PDFでダウンロード |

## 使用技術

| 分類 | 技術 | 選んだ理由 |
|---|---|---|
| 言語 | Python 3.12 | ライブラリの対応が安定している版 |
| 画面 | Streamlit 1.66 | Pythonだけで画面を作れ、無料で公開できる |
| グラフ探索 | NetworkX | 依存関係を点と線（グラフ）として扱い、幅優先探索で影響をたどる |
| データ処理 | pandas、openpyxl | 入力チェック、Excelテンプレートの作成・読み込み |
| 図 | streamlit-flow-component（React Flow） | ドラッグで線を引ける図をStreamlit上で使える |
| PDF | fpdf2、BIZ UDPゴシック（SIL Open Font License） | 純Pythonで扱いやすい。日本語フォントを同梱し、PDFには使った文字だけを埋め込む |
| AI | Anthropic 公式SDK、Claude Opus 5.5 | 回答の形（JSONスキーマ）を強制でき、プログラムで検証しやすい。モデルは設定ファイルで変更できる |
| テスト | pytest、Streamlit AppTest | 計算部分と画面の動作を、ブラウザなしで確かめる |

## 使い方（ローカルで動かす）

```powershell
# 1. 仮想環境を作って、ライブラリを入れる（Windows / PowerShell）
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt

# 2. 起動する
streamlit run app.py
```

ブラウザが開いたら、ホームの「サンプルで試す」→ 入力例のボタン → 「影響を分析する」の順に押すと、約3分で一通り試せます。結果の下の「AIによる分析のサンプルを見る」で、事前に生成したAIの結果を料金なしで見られます。「文章・資料から作る」の「サンプルの資料で試す」でも、事前に生成した候補を料金なしで見られます。

### AIを使う場合（任意）

`.streamlit/secrets.toml.example` をまねて `.streamlit/secrets.toml` を作り、APIキーとアクセスコードを書きます。このファイルは Git の管理から外しているので、GitHub には上がりません。

```toml
ANTHROPIC_API_KEY = "Claude Console で発行したキー"
ACCESS_CODES = ["配るアクセスコード"]
```

## テスト

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

- テストは **228件**（2026-11-03 時点、すべて成功）。正常な入力だけでなく、入力ミス（同じ名前、存在しない参照先、必須の値が空など）、AIのエラー（時間切れ・混雑・拒否・途中で切れた回答）も確かめています。
- **テストでは本物のAIを呼びません**（決まった答えを返す偽物を使う）。料金がかからず、何度でも同じ結果になります。本物のAIでの確認は、手動で行います。
- 画面のテストは、見た目（色・配置）やマウス操作（ドラッグ・クリック）までは確かめられないため、画面で目視確認しています。

## 費用と安全のための仕組み

公開版でAIを使うと、Claude API の料金がかかります。そのため、次の上限を設けています（値は `ai_settings.toml` で変更できます）。

- アクセスコードを知っている人だけが使える（利用記録には、コードそのものではなくハッシュ化した識別子だけを残す）。例外は「文章で説明する」で、誰でも使える（下記）
- 1人あたり機能ごとに月3回、全体で月150回まで。入力は、変更内容1,000文字・文章1,000文字・資料8,000文字まで
- 「文章で説明する」（アクセスコード不要）は、専用の月の予算（10ドル）の9割で止める。1人あたりの回数は接続元（IPアドレス）ごとに数える。IPアドレスは偽れるため完全ではないが、最悪でもこの予算で止まる
- 全体の月の予算（25ドル）の9割に達したら、AI機能を止める。あわせて Claude Console 側でも月の上限を設定する（アプリ側の制限だけでは請求の上限を保証できないため）
- 利用者の入力は、AIへの指示として扱われないようタグで囲む（プロンプトインジェクション対策）。AIには操作の権限を与えない
- アップロードしたデータや図で作ったデータは、画面を開いている間だけ使い、サーバーには保存しない

### 費用の目安（実測と試算の区別）

| 項目 | 値 | 区分 |
|---|---|---|
| AI分析1回のトークン数 | 入力 約5,700〜7,700／出力 約4,600〜6,000 | **実測**（4シナリオ、Claude Opus 5.5、2026-11-03） |
| AI分析1回の費用 | 約21円 | **試算**（実測のトークン数 × 公式単価 × 1ドル160円） |
| 文章から図のたたき台を作る1回の費用 | 約8円（63文字の文章） | **試算**（実測のトークン数から計算） |
| 資料から候補を作る1回の費用 | 約21円（946文字の資料） | **試算**（同上） |
| 月150回すべて使った場合 | 約3,140円 | **試算** |

モデルは、同じ4シナリオを Haiku 5.5・Sonnet 5.5・Opus 5.5 で分析して比べ、確認漏れの指摘の具体性がいちばん高かった Opus 5.5 を選びました（比較にかかった費用は約119円）。

## 開発の進め方（人とAIの分担）

この作品は、AIコーディングツール（Claude Code）を使って開発しました。

- **私（作者）が行ったこと**：解決する業務課題とコンセプトの設定、要件と完了条件の決定、画面の使い勝手の評価と改善の指示（例：図の方式をゼロから見直す、はじめての人向けのチュートリアル、未確認のつながりを目立たせる、データの箱を線にまとめる表示）、AIモデルを品質の比較結果から選ぶ判断、各段階の動作確認と承認
- **AI（Claude Code）が行ったこと**：コードとテストの作成、設計案と選択肢の提示、公式資料での仕様・価格の確認

## 今後の改善予定と、わかっている限界

- **未実装**：公開（Streamlit Community Cloud）、3案以上の比較
- PDFの表で、セルの右端の「）」「。」だけが次の行に送られることがある（日本語の行頭禁則を処理していない）
- 「文章で説明する」の1人あたりの回数は接続元のIPアドレスで数えています。公開先でIPアドレスが正しく取れるかは、公開後に確認が必要です
- 公開版では利用記録のファイルが消えるため、利用記録を外部のデータベースに移す必要がある
- 「登録情報にもとづく」は、AIが挙げた番号が**実在するか**の照合です。その番号が指摘の内容に合っているかまでは判定していません
- 分析は登録されたデータの範囲に限られます。登録されていないつながりは、「AIで確認漏れを調べる」の「未登録の影響の推測」で候補を出すにとどまります
- 図の ●（接続点）の大きさは、図の部品の内部の作りに頼って変えています。部品を更新するときは画面で確認が必要です
